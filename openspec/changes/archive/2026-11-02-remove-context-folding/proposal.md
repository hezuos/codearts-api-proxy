# Proposal

## Why

代理在**每个请求**上都会把完整对话折叠成一段文本再发给上游。实测一轮会话有 1893 条消息、折叠后仍约 100 万字符，中间历史被整段丢弃，模型因此看不到工具调用链，行为退化且 prompt 缓存全部失效。

折叠原本只是"上游拒绝超长 prompt"时的逃生通道，但默认预算只有 8000 字符，使它成了常态路径。它同时掩盖了一个更根本的问题：客户端被声明模型窗口为 100 万 token，而上游真实硬限约 19.6 万 token，客户端因此永远不会自己压缩上下文。

## What Changes

- 移除折叠与截断：完整历史一律逐字透传，代理不再改写、压缩或丢弃客户端消息。
- 移除 forceResync 机制：不再合成假工具调用（如让模型执行一条无意义的 echo）来触发"全量重置"。
- 移除主动重置：删除按累计 token 阈值触发压缩的逻辑及其提示消息。
- 移除链分叉修复：保留分叉分类（用于日志与缓存估算），删除依赖折叠的修复与重试分支。
- 上游返回 `ChatAgent.00001216`（prompt 超限）时，映射为明确的 `context_length_exceeded` 错误，由客户端决定压缩或摘要，代理不做静默补救。
- **BREAKING** 删除环境变量 `FULL_CONTEXT_MAX_CHARS`、`FULL_CONTEXT_MAX_CHARS_BY_MODEL`、`UPSTREAM_PROMPT_TOKEN_RESET_THRESHOLD`、`CHAIN_DIVERGENCE_REPAIR_ENABLED`。
- 使用侧需要同步调整：把 Zed provider 中该模型的 `max_tokens` 从 100 万改为接近上游真实上限（约 18 万），让客户端负责上下文管理。此项属于配置指引，不在代码内强制。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `full-context-injection`: 删除"注入/折叠/截断/缺失片段补发"要求，改为"历史逐字透传 + 超限诚实报错"。
- `chain-divergence-detection`: 删除依赖折叠的修复与重置要求，仅保留链状态跟踪与分叉分类。
- `error-classification`: 新增"上下文超限"错误类型及其对外的 OpenAI 兼容错误码。

## Impact

- 代码：请求构造、流式/非流式错误处理、恢复模块、提示消息、配置。
- 测试：折叠相关测试整体删除；恢复与主动重置相关用例改为验证"直传 + 报错"。
- 文档：环境变量表、架构说明、变更日志需同步删除上述配置项。
- 行为：真正超出上游硬限的长对话会直接失败并暴露原因，不再被静默截断；这是有意为之。
- 风险：移除兜底后，超长对话的首次失败会直接呈现在客户端，需依赖客户端自身的上下文压缩能力。
