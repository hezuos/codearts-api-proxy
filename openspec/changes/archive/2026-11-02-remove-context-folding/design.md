# Design

## Context

当前请求构造路径上存在三条都会"改写历史"的分支：历史超出字符预算时的折叠、上游客端返回分叉时的修复、累计 token 接近上限时的主动重置。三者共用同一套折叠实现，并共用一个 `forceResync` 开关；`forceResync` 还额外通过合成假工具调用来间接触发折叠。折叠实现自带一套角色标记、文本化工具调用、续接指令和中间截断策略。

约束：上游 v2 通道无服务端会话状态，每个请求都必须携带完整历史；上游对 prompt 长度有硬限制，超出时返回专用错误码。客户端侧声明的模型窗口远大于该硬限，因此不会自行压缩。

## Goals / Non-Goals

**Goals:**

- 请求历史与客户端发来的内容完全一致，可被逐字断言。
- 上游因长度拒绝时，错误语义明确、可被客户端识别。
- 删除折叠、修复、主动重置、假工具续命四类机制及其配置。

**Non-Goals:**

- 不实现代理侧的上下文压缩、摘要或裁剪（包括"只丢最旧消息"）。
- 不修改客户端配置，不替客户端判断其声明的窗口是否合理。
- 不改变链状态跟踪与分叉分类的判定逻辑本身。

## Decisions

**1. 删除折叠，而不是把阈值调大**

调大阈值只是把静默截断推后，行为仍然是"模型看到的历史与客户端发来的不一致"，且难以被发现。保留开关还会让两套请求语义长期并存。因此整块删除，历史无条件逐字透传。

**2. 长度拒绝映射为 `context_length_exceeded`**

上游专用错误码对客户端没有意义。映射到 OpenAI 生态通用的长度错误码，同时在 message 中保留 context length 字样，兼容只认文本的客户端。备选是透传上游原始错误体，但那会让客户端无法区分"长度问题"与"参数错误"。

**3. 流式响应的两段处理**

headers 尚未发送时可直接返回 HTTP 400；已经开始推流时无法改状态码，改为下发单个 SSE error 事件并正常结束流。备选是直接断开连接，但那会被客户端误判为网络故障。

**4. 彻底删除假工具续命**

合成工具调用（含让客户端执行一条无意义 echo）会把失败伪装成正常的一轮工具调用，既污染用户终端，也与"错误必须可见"冲突。一并删除，包括非长度类错误上的合成续传。

**5. 删除主动重置但保留 token 统计**

累计 prompt token 仍用于缓存命中估算与日志，只删除"达到阈值就压缩"的触发与提示，避免连带破坏观测数据。

**6. 配置项直接删除，不做兼容层**

保留但忽略的变量会让使用者误以为仍然生效。直接删除并在变更日志与架构文档中标注为破坏性变更，符合"代理不再提供上下文管理"的定位。

## Risks / Trade-offs

- **超长对话会直接失败**（以前被静默续命）→ 文档与启动日志提示调整客户端声明的窗口；错误码语义明确，客户端可据此摘要或新建会话。
- **上游对超大 body 可能返回 413 而非专用错误码** → 把 413 一并映射到同一错误类，避免客户端看到无法理解的原始错误。
- **删除假工具续命后，个别非长度错误会中断会话** → 这是有意为之；若确有需要，后续可单独设计"显式失败 + 用户可见提示"，而不是伪装成工具调用。
- **旧部署的环境变量被移除** → 变更日志与架构文档明确标注；变量本身不再被读取。
- **折叠相关测试整体删除会降低覆盖** → 用"逐字透传"的等价断言补位，覆盖多轮、工具调用、超大 system 三类输入。

## Migration Plan

1. 先调整使用侧：把客户端中该模型的声明窗口改到接近上游真实上限。
2. 按依赖顺序删除代码：请求构造的折叠分支 → 恢复模块的假工具调用 → 提示消息中的压缩通知 → 配置项与文档。
3. 同步测试链：删除折叠测试文件，改写恢复与主动重置用例为"直传 + 映射错误"。
4. 更新环境变量表与架构说明，变更日志标注破坏性变更。
5. 回滚策略：整体 revert 即可，本次不涉及数据迁移或存储格式变更。
